Open-web benchmark update

The model starts with an investigation brief and zero source URLs. It chooses where to look and has to show where each finding came from.

What the harness gives the model

The current cases allow web search, page fetch, downloads, a calculator and sandboxed code. The model submits findings with citations to observations it received through those tools.

We check the findings and their evidence. A no-retrieval control helps catch answers the brief gives away. The Kodiak runs had a 25-call diagnostic guard and no elapsed-time budget.

Harder cases

We added a museum restitution case that asks the investigator to reconcile a catalogue correction, two ownership lists and the signed transfer. Exact counts only earn full credit when the records support what those counts describe.

With four source links supplied, both models answered all 12 reviewed claims. The first open-web runs hit the call guard after search requests failed.

A rerun with working search

We reran both models from the same briefs with no starting links. They used the same search backend, which returned URLs for every query. The models still had to open and check the sources.

Both models matched all 13 reference findings for the Kodiak buoy case in 14 and 15 calls. Their calculations cited both NOAA archives and the USGS origin time. On restitution, both reached the key records and used all 25 calls without submitting.

Give the agent a final report call

A second restitution run reserved call 25 for a report. The model could still finish earlier. Astra submitted in 18 calls and Sol used the reserve. I checked the cited evidence and found support for all 12 claims in both reports. This makes restitution a development case for testing when agents decide they have enough evidence.

Can tighter limits make the cases harder?

A Connecticut case asks the model to reconstruct how residents counted under the old counties overlap the new planning regions. Both models recovered all 19 populated overlaps in 13 calls. They used different public records to check the join.

In a separate 12-call run, Sol submitted the full reconstruction. Astra also calculated all 19 overlaps, but an extra brace in its final response caused the harness to reject it. The tighter limit exposed a submission failure. Without tools, Sol still got 13 of the 19 overlaps and the main conclusion. I’d keep this as a reconstruction check and look for cases where the decisive finding depends on evidence the model has to discover.

Running the benchmark in Harbor

Harbor scheduled a live Connecticut trial. The task container had no network. The model reached public records through the same logged tools as before. Sol recovered all 19 overlaps in 12 calls, and Harbor collected the report.

A separate calculator run passed in a second offline container. That check confirms that Harbor can hand a submitted answer to a verifier. The investigation still needs independent evidence review before it contributes a benchmark score.

Mini and OpenHands on the same case

Both harnesses ran in Harbor with the same model, public-source gateway and 25-call ceiling. Mini submitted in 12 calls and OpenHands in 14. Both recovered all 19 overlaps. One case gives us a working comparison setup. We still need repeated runs on independently reviewed cases.

Checking the evidence before scoring

The audit checked that the two harnesses used the same task, model, tools and call limits. Reviewers can now see the submitted answers and the source text and images each model received. The review hides the harness name and leaves the judgments open.

Which station supplied the chart?

The Mauna Loa case asks agents to trace a published CO₂ chart back to the station that took each reading. Both models reconciled the three files within the 25-call ceiling. Sol took 18 calls in mini and 14 in OpenHands.

Without tools, Sol recognized that the station changed and supplied none of the exact dates or counts. A separate 12-call run spent five requests on links that returned 404 and submitted a partial report. The case lets us inspect how agents recover when they start from the wrong link.

What a tighter limit changes

In a new U.S. Census case, agents checked whether overseas counts changed who got a House seat. Both reproduced the four apportionments. Astra found a historical workbook and finished in 12 calls. Sol finished in 19. A separate 12-call Sol run gave the right figures but left the full allocation unverified. Sol also gave the key figures from the prompt alone, without checking the records.

We review the finding and its evidence separately. The main track keeps public search and local analysis available. A lower call ceiling tests whether an agent can finish and verify its work with fewer attempts. The hardest cases will need evidence from records that play different roles.

Recognizing a place and checking a caption

With two satellite images and no tools, Sol recognized the lake but could not date the scenes. With the web, Astra and Sol found both original releases and a separate satellite observation. They submitted in 19 and 25 calls. The case gives us a way to test visual verification alongside recognition.

When the source disagrees with itself

Both models found the eight historical gauge files under a 25-call ceiling. Neither finished the measurement comparison. At 35 calls, Astra reconciled the clocks, spotted the conflicting cancellation times and reconstructed the gauge readings. Sol still left the calculation open. The author checked the result under both reported times.

Training

The local Qwen pipeline has sampled its own tool commands, taken an evidence-reward update and reloaded the adapter. That check used arithmetic tasks. The full Qwen3.8-27B checkpoint completed one supervised update on a reviewed filing action. Validation action loss fell from 0.0380 to 0.0309 on one example from a separate development case. Reloading the adapter reproduced that loss. The base and supervised checkpoints fetched the same two documents. The base run was cut off at 170 output tokens midway through its third action. Replaying that turn with the supervised checkpoint gave the same result. With a higher token limit, the model wrote the full command but left the JSON object open. With a stricter JSON constraint, Qwen completed the archived action and the sandbox extracted text from both filings.

In fresh runs, both Qwen checkpoints fetched and extracted the two filings before exceeding their context limit. With shorter tool excerpts, the base checkpoint reached the report call. Its draft recovered the four numeric values, then ran out of output tokens. The draft also had the wrong threshold verdict.

The reward trainer now checks probabilities under the same JSON grammar used to sample actions. A reduced vision checkpoint completed and reloaded an update using fixture rewards.

Two full Qwen3.8-27B rollouts on the revised filing brief earned evidence rewards of 0.5 and 1. Both found the right values. One report omitted a crosswalk citation. A separate cached replay reproduced all six sampled actions and their token probabilities. The full checkpoint took one reward update. The changed adapter reloaded in a fresh process and generated a valid tool action on a retained prompt. The next check is performance on withheld cases.
