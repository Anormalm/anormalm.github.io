How the agent would construct an investigation

Implementation proposal for discussion. The agent receives the tools; the next work is to build and review the investigation loop.

What the agent receives

Give the agent an investigation brief, starting artifacts and a documented set of tools. The brief states the question, historical or geographic scope and the intended report. Tool interfaces are provided by the harness before the run. The agent constructs the investigation, rather than implementing its own search or OCR adapter. There is no separate investigation-skill library.

Construct the initial plan

The first model call turns the brief into working questions. For each question, record why it matters, what is already known and what observation might help. These questions are provisional: the model may add, merge or drop them as it reads. The prompt should not prescribe a complete source route or supply the curator’s answer.

Keep a usable investigation state

Maintain the brief, active questions, candidate entities, provisional claims, source observations, unresolved conflicts and the current plan. Each observation has a stable identifier, original URL or artifact reference, retrieval timestamp and locator. A claim records which observations support or contradict it. Keep the model’s short action rationale separately from the source evidence; it is not itself evidence.

Choose and execute the next action

At each iteration the model selects one question and a permitted tool call. It explains briefly what it expects the result to clarify. The controller validates the tool and arguments, executes the call and stores the response or failure. Search finds leads; page, PDF and image tools inspect sources. Metadata, OCR and geographic analysis return derived observations linked to the original file. Those outputs still need interpretation.

Update the account and revise the plan

After a result, the model states what changed: a candidate was ruled out, a claim gained support, a contradiction appeared or no useful evidence arrived. It checks whether records describe the same entity, role and event. Publication time, observation time and event time stay separate. The model then revises its working questions and chooses the next action. Repeated copies of one record should not be treated as independent corroboration.

Decide when to report

The investigation is open-ended. Do not use elapsed time as its research budget or prescribe a fixed number of lookups. The model may propose reporting when it has a coherent supported account of the scoped question and has addressed the important alternatives. It must explain remaining gaps and why further searching seems unlikely to change the account. Reviewers should examine premature stopping as well as unsupported conclusions. Record calls, tokens, elapsed time and cost as observations; any resource limits need a separate explicit decision. Provider timeouts and user cancellation remain ordinary engineering controls.

Produce a report that can be reviewed

The final report contains the answer to the brief, a dated account where relevant, source-linked findings, unresolved conflicts and limitations. Each substantive claim cites an observation and an exact source location. A separate validator checks that cited observations were delivered and locators are present. Human review assesses whether the passages support the claims and whether the investigation covered what mattered. The current closed-field scoring does not establish a score for this open-ended setting.

A concrete example to develop

For the A-23A brief, the initial questions could concern the dated observations, fragment identities and sequence of changes. NASA and USNIC records offer starting material. The retained USNIC notice has an 18 August dateline and 30 August wording in its body and figure. A planned follow-up could look for another dated copy or independent observation. If that does not settle the discrepancy, the report preserves it. This is a proposed use of the existing source material, not a new agent trace.

Build one complete path first

First finish manually checking a selected case’s wording, source support and reference interpretation. Then implement the shared tool registry, a search provider, source/artifact reading and the evidence store. Connect a planner to that state and add the execution/update/report cycle. Run one investigation with complete tool traces and inspect where its plan changes or stalls. Only then extend to more cases and compare instruction detail. Both instruction conditions receive the same tools; one gets only the brief and the other also gets a generic investigation guide.

What is ready and what remains

The case material and source-linked walkthroughs exist, but manual checking is unfinished. Lifan’s assessment is that the material is worth building on; this is not an independently validated quality claim. The current model harness fetches supplied pages. General search and the wider artifact, image and geographic interfaces still need integration. This document is an implementation proposal for the next work, with no new model result or training claim.
